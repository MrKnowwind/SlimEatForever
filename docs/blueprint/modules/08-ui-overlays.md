# 模块 08：结算、弹窗与通用 UI

状态：已有多套正式资源，但组件体系尚未完全统一。估算完成度 58%。

## UI 层级

- 主场景 HUD：depth 20。
- 遭遇/战斗：约 depth 40–46。
- 结算：depth 50。
- 进化树：depth 55，树内容由专用相机渲染。
- 节点详情：depth 65，并隐藏树相机。
- Toast：depth 70，并要求树相机忽略。

任何新弹窗都必须确认主相机和树专用相机的 ignore/visible 关系，避免后创建的相机把底层内容重新盖到弹窗上。

## 进化树详情页

- 使用简单面板框 v3，不内置分区、插槽、文字或按钮。
- 代码负责节点图标、标题、描述、进度、条件、染色选择和操作按钮排版。
- 详情页打开时树内容不得透过或覆盖面板。
- 未知、已知锁定、可购买和已完成使用同一布局，只改变内容和状态色。

## 按钮体系

当前存在：通用按钮四态、结算主/次按钮、进化树完成按钮 v2、详情操作按钮。

目标组件分类：

- Primary：确认、重新开始等主要行为。
- Secondary：返回、进入其他页面等次要行为。
- Tree Complete：固定在进化树底部的页面完成按钮。
- Compact：速度切换、颜色选择等小控件。

不要再让完成按钮和详情面板共享同一背景资源，也不要用任意拉伸的完整图片承担所有尺寸。

## 字体与文本

- 中文字体暂定 `Microsoft YaHei, PingFang SC, sans-serif`。
- 标题、主要数值、正文、辅助信息采用整数字号。
- 像素 UI 可使用 1–3px 暗色描边，但避免模糊阴影。
- 遭遇和战斗仍有 serif/sans 混用，后续统一。

## NineSlice 方向

早期目标是 Panel/Button 采用 NineSlice。目前多数函数仍使用 `fitAsset()` 等比缩放，优点是不会非均匀拉伸，缺点是无法自由适配内容尺寸。

后续若接入 NineSlice：

- 只拉伸无细节的边段与中心。
- 四角和金属装饰保持固定像素尺寸。
- 不把按钮文字烘焙进资源。
- 为每种面板记录安全内容区，而不是靠截图手调。
