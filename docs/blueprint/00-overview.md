# 项目总蓝图与进度总览

最后更新：2026-09-10

## 一句话目标

制作一款暗色地牢像素风的史莱姆吞噬成长小游戏：玩家在袭击间隙喂养史莱姆，通过自动战斗取得战利品，失败后用魂晶推进永久进化树，再开启下一局。

视觉架构的核心原则是：**程序负责结构、数据、布局、状态与交互；固定像素 Sprite 负责正式外观。**

## 当前阶段

项目已经是可玩的纵向原型，主循环、成长、战斗、结算、永久升级与存档均已存在。当前工作重点仍是正式美术资产化和 UI 视觉收口，而不是扩张玩法规模。

以下百分比是产品蓝图完成度估算，不等同于测试覆盖率：

|---|---:|---|
| 核心游戏循环 | 82% | 可玩，仍需数值与边界体验调优 |
| 像素美术基础系统 | 75% | 资源目录、映射、nearest 与处理脚本已建立 |
| 主场景与生产系统 | 68% | 功能完整度较高，HUD 与部分反馈仍偏程序绘制 |

## 已确定的产品与视觉决策

- 画布为 `1160 × 720`，使用 Phaser 4、Vite、FIT 居中适配。
- 全局关闭抗锯齿，资源使用 nearest-neighbor，尽量保持整数坐标和像素边缘。
- 视觉基准采用当前史莱姆的像素密度；暗色地牢、蓝绿色石材、旧金色金属为 UI 主语言。
- 当前项目只有两种史莱姆视觉形态：无眼睛的初始幼体，以及更大、有脸且动作更丰富的进化形态。
- 进化树连线、Anchor、Junction、节点位置和滚动范围由代码计算，不烘焙进图片。
- 节点壳与能力图标采用固定 Sprite；状态统一为 `owned / available / locked / unknown`。
- 进化树固定水平范围，不允许玩家缩放；内容超出可视区时垂直滚动，并由专用相机裁剪。
- 新食物分支直接展示在树结构中；未满足揭示条件时显示未知，前置完成后显示真实节点，但仍须满足购买条件。
- 池塘和盐矿是独立场景产出容器，分别生产鱼肉和盐结晶。
- 初始敌人是木剑见习者，第二波是老练猎人，后续为盾卫、弓手、术士组成的小队。
- ImageGen 负责美术母版，处理脚本负责裁切、透明度、网格和帧尺寸，游戏只加载 `assets/pixel/` 下的正式资源。

## 当前最高优先级

1. 在实际预览中复核新详情面板 v3、进化树裁剪/滚动和结算面板对齐。
2. 将主 HUD、战斗信息卡、行动轨道与速度按钮从临时几何组件迁移到正式资源。
3. 为盾卫、弓手、术士制作一致的 SpriteSheet，移除战斗中最后一批程序拼装人形。
4. 统一遭遇标题、战斗标题、数字与中文字体层级。
5. 清理已被固定资源替代但仍留在 `pixelArt.js` 和 `main.js` 中的不可达旧绘制代码。

## 明确待决问题

- 产品口径只有两种视觉形态，但当前数据仍有 `evolution-2` 和“成熟体”命名；需要决定它是第二个能力等级，还是应合并/改名，不能自然扩展成第三套角色外观。
- `newFood` 在进化一级后可解锁，但场景生成与吞食盐/鱼目前要求 `evolution >= 2`；需要确认这是否是有意的二段门槛。
- Panel/Button 当前多为整图等比缩放，还没有形成真正统一的 Phaser NineSlice 组件。
- 现有正式背景是一张完整地牢图，还未达到早期蓝图中的 TileSet 化目标。

## 不在当前阶段扩张的内容

- 新 Boss、大量新敌人或装备系统。
- 第三种史莱姆视觉形态。
- 复杂 Paper Doll 装备分层。
- 在现有 UI 尚未收口前大规模增加技能树分支。
